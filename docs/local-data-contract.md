# Local storage, providers, and backup

## Data boundaries

- Agents, agent configuration, provider metadata/configuration, model catalog entries, reasoning preferences, topics, messages (including provider-bound opaque reasoning context, search activity, and structured citations), and attachment references are local application data.
- Room is the source of truth for structured data; appearance, the opt-in search preference, and the configured SearXNG endpoint remain in Preferences DataStore.
- Inference requests are sent directly from the device to the selected provider. LobeHub sign-in, hosted sessions, tRPC, and Gateway are not part of the runtime.
- Chat, provider, and agent data stays on the device except for prompts/attachments sent to the selected inference endpoint. Subscription device login, token refresh/exchange, and cloud service-account authorization use the corresponding provider's authentication endpoints. Model discovery uses provider catalog APIs.
- Opt-in independent search sends only the latest user question to the configured SearXNG endpoint; retrieved source snippets plus conversation context go to the selected inference provider. Native OpenAI search is provider-hosted and may send queries/relevant content to OpenAI's search partners. No default public search instance is contacted.

## Provider credentials

API keys, OAuth access/refresh tokens, exchanged Copilot bearer tokens, and other credential fields are encrypted using Android Keystore AES-GCM. The per-installation Keystore key is non-exportable; encrypted credential data is stored under `noBackupFilesDir`, never in the Room database or logs. This prevents a restored ciphertext from being mistaken for a usable credential when its device-bound key is unavailable. Settings snapshots exclude internal OAuth tokens. Settings writes and token rotation share provider-level exclusion so a stale form save cannot restore old refresh tokens.

Because Android Keystore keys are not restored with app data, credential ciphertext is intentionally excluded from Android Auto Backup and device-to-device transfer. Restore provider names, endpoints, model settings, agents, conversations, and local files, then re-enter credentials or reconnect the subscription account. OAuth disconnect is local credential removal, not provider-side revocation.

## Android backup

`backup_rules.xml` and `data_extraction_rules.xml` include the Room database, the UI Preferences DataStore file (`datastore/ui_prefs.preferences_pb`), and `files/local_files/` for cloud backup and device transfer. Legacy server, cookie, and remote-profile DataStore files are not included. The provider secret vault is kept in `noBackupFilesDir` and is not included. Android/Google Play backup remains subject to the user's device backup settings and platform limits.

## Provider metadata

`core/data/src/main/assets/provider_catalog.json` bundles 85 providers and 1,886 model entries from the [LobeHub Model Bank](https://github.com/lobehub/lobehub/tree/6c7a6fb033e443bc27bf34cbd5509ab3db7f22f3/packages/model-bank), pinned to commit `6c7a6fb033e443bc27bf34cbd5509ab3db7f22f3`. It excludes the `lobehub` hosted-service provider. The snapshot includes names, descriptions, provider documentation/key links, endpoint hints, model types, abilities, context/output limits, and other upstream model metadata. It is static app data; there are no runtime LobeHub requests.

The local provider form combines catalog hints with maintained `ProviderConfigSpec`/`ProviderSpecialFields`; `ProviderInvocationSpec` is the common source for actual chat-adapter support and service defaults. Four current Kimi Code aliases supplement the static snapshot, initially disabled. Existing bindings and custom endpoints are preserved; only exact obsolete official OpenCode/Straico defaults are migrated.

All 85 catalog providers remain visible. Local chat adapters cover 81 providers, including cloud-native and subscription transports; GitHub Models' retired public endpoint reports an explicit service-retirement error, while a configured compatible proxy can still use its adapter. Fal, BFL, ComfyUI, and Replicate contain only image models and are not exposed as chat. Individual image/video/embedding/speech/realtime models remain unavailable to the conversation UI; metadata presence alone is not proof of chat compatibility.

Fresh installs seed every provider and model as disabled. Upgrades preserve activation choices rather than resetting them; newly added entries remain disabled. Chat model pickers expose only chat-capable models that are enabled and whose provider is enabled.

## Invocation contracts

- OpenCode Go sends `x-opencode-session` from the persisted local topic ID on every turn, including Anthropic, Responses, and Gemini routes. Standalone connectivity probes receive an independent UUID. It sends the app's real User-Agent/client identifier, not a spoofed approved coding client. Current [Go](https://opencode.ai/docs/go/#endpoints) and [Console/Zen](https://opencode.ai/docs/zen/#endpoints) routes distinguish `/inference/…/openai`, `/anthropic`, and `/google`; the model-list endpoint is not the inference root.
- AIHubMix, NewAPI, and ZenMux select protocol-native routes. Direct provider rules handle authentication headers, sampling ranges, output-token parameter names, thinking controls, and historical reasoning formats. OpenAI-only legacy instruct models use Completions rather than Chat Completions. Straico uses its documented v2 `/chat` route, not a fabricated `/chat/completions` suffix.
- Inference is stream-first. Native OpenAI GPT/o-series models use [Responses](https://developers.openai.com/api/docs/guides/migrate-to-responses) where supported; chat-only/audio/search-preview and legacy instruct models retain their required endpoints. Native Responses requests disable server-side storage, and OpenAI encrypted reasoning is requested for local multi-turn replay. The obsolete broad o1/o3 nonstream overrides are removed. [o1-pro](https://developers.openai.com/api/docs/models/o1-pro), [computer-use-preview](https://developers.openai.com/api/docs/models/computer-use-preview), and Straico's JSON API retain their nonstream request contracts.
- SSE events are assembled through blank-line boundaries, including multiline data; nonstream JSON, Ollama NDJSON, and Bedrock CRC-checked binary event streams have separate decoders. Ollama and Bedrock continue through HTTP EOF so trailers and late provider/transport errors are not silently discarded. HTTP and in-stream provider errors propagate to the UI. Cancellation closes the active inference call and preserves coroutine cancellation instead of leaking the socket-close exception; genuine I/O failures still propagate.
- Responses encrypted reasoning items are stored with their assistant message and replayed only when provider and model both match. Unsigned compatible reasoning uses the provider's declared passback format; plain reasoning text is not synthesized into signed Claude blocks.
- Connectivity invokes the selected/configured check model and decodes its actual response. Listing support is independent: providers without deployment/model-list APIs use catalog selection plus a real connectivity probe. Non-chat remote entries are filtered; newly discovered models remain disabled. Fetched models merge listing fields with the bundled catalogue (exact ID, then a provider/family match) and conservative ID inference for display name, family, generation, and reasoning/tool abilities; unknown token limits are not invented. Provider detail counts Room model rows rather than the static catalogue count, and the same enriched abilities drive the model-detail reasoning controls.
- Azure uses deployment/resource endpoint and API-version semantics; Bedrock supports bearer keys or region-scoped SigV4 credentials with session tokens; Vertex supports express Gemini keys or service-account OAuth, with OAuth required for Claude. Credentials, IAM permissions, enabled deployments/models, region, quota, and subscription terms remain external prerequisites.

The implementation audit used the pinned [upstream model runtime](https://github.com/lobehub/lobehub/tree/6c7a6fb033e443bc27bf34cbd5509ab3db7f22f3/packages/model-runtime) and provider documentation. [GitHub Models retirement](https://docs.github.com/en/github-models) prevents its former public service from working regardless of credentials. [Kimi Code](https://www.kimi.com/code/docs/en/) supplies the supplemental current model IDs; [Xiaomi](https://platform.xiaomimimo.com/docs/en-US/api/chat/openai-api) documents its `api-key` and thinking contracts. The [Straico v2 announcement](https://straico.com/platform-changelog/%F0%9F%9A%80-new-openai-compatible-api-v2/) was available through indexed search; direct documentation fetch failed DNS. None of these source checks prove authenticated account availability.

## Web search

`WebSearchPreferences` exposes an atomic `WebSearchSettings(policy)` snapshot from `ui_prefs`. The dedicated search page edits the default `WebSearchPolicy`: `OFF`, `NATIVE`, or `PROVIDER` with exactly one provider ID. The root Settings page contains only its navigation entry. Defaults start off and survive restart/backup. Enabling a search provider does not select it or change the default.

`WebSearchProviderRepository` persists non-secret provider configuration in the same DataStore. `WebSearchCatalog` preconfigures Tavily, Brave, Exa, Serper, SerpApi, Bocha, Firecrawl, Linkup, You.com, and SearXNG; new built-ins start disabled, and SearXNG has no public endpoint. Custom `custom-UUID` records choose one supported API protocol and a full endpoint, and support edit/delete. Built-ins cannot be deleted or have their identity/protocol changed. API keys are isolated under `search.<provider-id>` in the existing encrypted no-backup `ProviderSecretStore`; no key is stored in DataStore/Room/SavedStateHandle. A null key update retains the key; empty clears it, and enabled key-required services cannot be saved without a key. Config/credential updates finish consistently or restore the previous secret on failure. Restoring a configuration backup does not restore credentials; missing keys fail explicitly at use.

`AgentConfig.webSearch` is a nullable `WebSearchPolicy` in the existing Agent JSON payload. Null means inherit; explicit off/native/provider wins over the default. The editor uses a compact selection dialog, only offers enabled external services, and shows missing/disabled selected services without replacing them. Save, reset-to-inherit, and duplicate preserve the typed policy; no Room schema migration is needed. One-time migration removes the old keys: a saved SearXNG URL becomes a configured/enabled `searxng` service; old global off stays off, and on selects SearXNG when configured, otherwise native. Legacy Agent false becomes off, true selects configured SearXNG or native, and null/absent inherits. Malformed old Booleans or new policy payloads fail rather than guessing a route.

Chat displays the effective route read-only and captures the policy before starting each send. Later default changes affect inherited Agents and future sends only. Preference/Agent load failures block sending until a successful refresh; unsupported native selection and missing/disabled/unconfigured external selection are rejected rather than falling back. The backend rechecks the selected provider and credentials before searching. Selecting an external service never adds the model's native search tool, even when the model is native-search-capable.

Supported builtin OpenAI models use the stable Responses `web_search` tool only in native mode. Their native eligibility and valid reasoning efforts are explicitly allowlisted; unsupported effort is rejected rather than silently increasing computation/cost. External mode exposes the selected service as a model-callable `web_search` function tool; the model decides whether to search, and the app invokes exactly that service only for requested queries through `WebSearchClient`, returning documented-protocol results with at most five safe, distinct HTTP(S) sources and snippets. Tool-call rounds are bounded to five per answer; incomplete or truncated tool arguments are never executed, and malformed arguments return a tool error to the model. HTTP/API errors, blocked/non-JSON/malformed/empty output fail visibly. Requests have bounded timeouts and a 1 MiB response limit, no redirect/retry/fallback, no inherited logging/cookie/authentication follow-ups, and sanitized error messages. Cancellation closes the active socket and remains coroutine cancellation. Official protocol references are linked in the README; loopback verification is not authenticated live-account verification.

Search results are added only to the in-flight tool conversation, not to the persisted user message or assistant transcript; the model receives them as untrusted tool output and decides whether to search again or answer. The `web_search` tool is offered on OpenAI-compatible, Anthropic, Gemini, Ollama, and Bedrock routes; incompatible routes fail explicitly rather than silently retrieving. Snippets are explicitly untrusted evidence; the model is told not to follow embedded instructions, invent sources, or claim full-page reads. Source-only citations are emitted as soon as results arrive. Native Responses search parses real call progress, query/action events, URL annotations, content-part offsets and terminal snapshots; repeated snapshots do not duplicate text, encrypted reasoning, or sources. Ordinary requests do not allocate native search transcript state.

`ChatMessage.searchActivity` and `citations` are optional/defaulted JSON payload fields, so existing Room rows need no schema migration. Citation offsets are full-answer Kotlin UTF-16 indices. UI-only numbered links are inserted only at reliable Markdown-safe spans; unique source cards and safe HTTP(S) link previews remain available otherwise. Raw answer content is unchanged for copying, persistence and later conversation history. Rendering cards does not fetch pages or third-party favicons. Stopped/incomplete historical searches never display an active spinner.

The complete response buffer owns query/source accumulation, source-only-to-anchored upgrades, and cancellation persistence. Non-cancellation producer failures close the flow with their original cause rather than cancelling its buffer; queued text/search metadata drains before the error reaches the consumer. Search-only stopped messages can therefore retain real sources without a fabricated answer or successful completion.

Google Grounding is deliberately not requested, preserving the chosen full-local-history workflow without storing/redistributing its restricted search metadata or omitting required Search Suggestions. Gemini and other providers instead use independent retrieval when configured. Service/operator terms, endpoint reachability, provider accounts, model eligibility and billable usage remain external prerequisites.

## Response completeness

Known positive model output limits are sent through the correct protocol field (`max_tokens`, `max_completion_tokens`, `max_output_tokens`, Gemini `maxOutputTokens`, Bedrock `maxTokens`, or Ollama `num_predict`) without a shared 4,096-token cap. Provider-specific documented constraints still apply. Optional limits are omitted when the catalog does not know them; Anthropic-compatible Messages requests require an explicit value and use 8,192 only for an unknown model. ChatGPT subscription requests omit the public API output-limit field because that backend manages its own limits.

Generation success requires a protocol completion signal: a final OpenAI finish reason or `[DONE]`, Anthropic `message_stop` (with the preceding stop reason), Responses completed/incomplete status, a final Gemini finish reason, Ollama `done`, or Bedrock `messageStop`. A complete nonstream JSON response is evaluated with its finish reason/status where present. EOF after partial text without a terminal signal is an interruption, not a successful answer. Final text arriving in the same event as the finish reason is retained.

OpenAI `finish_reason` and Gemini `finishReason` are generation metadata, not permission to close the SSE connection. Subsequent deltas, finish reasons, usage trailers, and errors are still read. A compatible server may close without `[DONE]`; a recorded finish reason suffices at EOF only if no later content made it stale. A reason followed by new content needs a fresh finish reason or the actual stream terminator. Length/filter/tool/failure reasons remain distinct rather than being overwritten by a generic `[DONE]` success.

Each assistant message can persist a typed completion status and raw provider finish reason. Output exhaustion, interrupted transport, user stop, filtering, tool requests without configured tools, and provider failure remain distinct in history. Legacy messages have no recorded status; they are not retroactively guessed to be complete or incomplete. Reasoning-only partial output is retained as well.

The full per-generation buffer is independent of the throttled UI snapshot. Stop/cancellation saves that buffer, its original topic/provider/model, and any opaque reasoning context; navigation cannot redirect it into another conversation. An older request finishing its save cannot clear or overwrite a newer generation. No automatic retry or hidden continuation request is issued: the user can explicitly ask to continue from the retained history.
